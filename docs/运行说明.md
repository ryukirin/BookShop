## 固定安装

在仓库根目录执行，使用电脑已有的 Python 3.11.3：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install --require-hashes -r requirements-test.lock
```

生产运行只安装 `requirements.lock`；`requirements-test.lock` 另包含仅测试用 Pillow 9.5.0。锁使用 Windows x64／CPython 3.11 wheel 哈希，不适用于其他平台。版本和许可证见 `sbom.json`、`THIRD_PARTY_NOTICES.md`；安装工具 pip 不纳入应用包集合。各发行包的完整许可证随 wheel 安装，重分发必须保留。

本次已在新建的隔离虚拟环境中以固定 wheel 缓存、`--no-index --require-hashes` 完成离线安装，证明锁文件能够复现；如新电脑需完全离线，操作者应先在联网环境用同一锁下载 wheel 到仓库外缓存。

## 外部配置

不要把真实密钥写入仓库或 `config.example.ps1`。推荐在 PowerShell 7 的当前会话设置外部环境变量；下面路径由仓库位置计算，不包含真实秘密：

```powershell
$env:BOOKSHOP_DATABASE_PATH = Join-Path (Get-Location).Path 'instance/bookshop.db'
$env:BOOKSHOP_UPLOAD_DIR = Join-Path (Get-Location).Path 'instance/uploads'
$env:BOOKSHOP_LOG_PATH = Join-Path (Get-Location).Path 'instance/logs/bookshop.log'
$env:BOOKSHOP_SECRET_KEY = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

密钥解码后至少 32 字节；不要输出、提交或复用示例值。缺失、短值、占位值、不可写路径均拒绝启动，无默认密钥或数据库回退。应用会验证目录可写性，并创建空数据库文件用于路径检查；业务 schema 尚待 BATCH-002 初始化。

如使用持久配置，复制示例到仓库外的个人受控文件，只允许运行账号访问；`scripts/start.ps1 -ConfigPath $personalConfig` 与停止脚本均可读取该外部文件。密钥轮换、业务备份和恢复操作将由后续批次文档补齐，当前不得擅自覆盖已有业务库。

## 启动与停止

建议从已安装固定依赖的虚拟环境调用脚本，先激活其 PowerShell 环境：

```powershell
. .venv/Scripts/Activate.ps1
pwsh -NoProfile -File scripts/start.ps1
```

隐藏后台启动：

```powershell
pwsh -NoProfile -File scripts/start.ps1 -Background
Invoke-WebRequest http://127.0.0.1:8000/BookShop/health
pwsh -NoProfile -File scripts/stop.ps1
```

停止脚本在配置数据库的父目录创建 `bookshop.stop`；gevent 等待在途请求后退出并清除自己的 `bookshop.pid`。脚本超时不强制杀进程，应先查日志。前台 Ctrl+C 也走停止逻辑。后台启动提示中的 PID 可能是 Windows 虚拟环境启动器 PID；以服务写入的 PID 文件为准。

PID 文件属于本机运维状态，不是业务数据。启动时只读查询旧 PID：仍存活则拒绝重复启动，确认已退出则回收残留 PID 并记录恢复日志。损坏 PID 文件或查询失败不会静默覆盖。

## 日志与测试

日志使用 UTF-8 JSON，单文件 1 MiB，保留 7 份轮转文件。包含请求关联 ID、路径、方法、状态、错误类别及脱敏栈位置；不记录查询字符串、密码、签名密钥、Session ID、异常正文或敏感请求正文。

BATCH-001 门禁：

```powershell
$env:BOOKSHOP_VERIFY_ENV = '1'
.venv/Scripts/python.exe -m unittest tests.test_runtime tests.test_routes.FoundationRouteTests tests.test_delivery.FoundationDeliveryTests
```

`BOOKSHOP_VERIFY_ENV=1` 的安装集合精确核对只在干净虚拟环境运行；现有全局 Python 环境可能含无关包，不能冒称为干净交付集合。CI 已创建 Windows 无交互检查，但尚未推送或在 GitHub 实际运行。

后续批次的业务测试仍为红灯，当前不要以 `unittest discover` 的整套红灯否定或假报为骨架通过。证据分别存于 `artifacts/migration-evidence/TEST-###/`；本批尚需按任务 2.3 验证目标骨架检查点的回退，才能进入 BATCH-002。
